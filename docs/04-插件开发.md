# 04 · 插件开发

## SDK 1

普通插件使用 JavaScript / TypeScript，入口打包为自包含 ESM，默认导出包含 `onload(context)` 的类，可提供 `onunload()`。清单、入口、样式为 `manifest.json`、`main.js`、可选 `styles.css`。不支持直接 require Obsidian、Electron 或 Node.js。

在设置的插件页选择“安装本地插件”，选择含清单的目录。运行示例见 `examples/plugins/reading-time`。

插件代码安装到系统应用数据目录，启用状态与插件设置按工作区保存，实例按工作区隔离。关闭工作区或停用时清理注册资源。SDK 类型见 `src/plugins/sdk.ts`。

| 接口 | 用途 |
|---|---|
| addCommand | 注册命令并进入命令面板 |
| addSettings | 注册文本、数字、开关设置 |
| files.read/write/list | 工作区文件访问；写入经过文档与版本检测 |
| editor | 读取文档与选择，插入文本 |
| registerEditorExtension | 注册共享 CodeMirror 6 的扩展 |
| registerCodeBlock | 渲染特定 Markdown 代码块 |
| registerPanel | 注册独立面板并返回清理函数 |
| onFileChange、register | 注册监听或资源清理 |
| loadData、saveData | 工作区内的插件设置 |

## 运行边界

这是用户选定、审查过源码的可信插件模式。与主界面同页面运行的 JavaScript 能访问页面环境；清单 permissions 是声明，不是安全隔离。长时间计算应移入 Worker 或宿主服务。插件 SDK 不向插件提供根目录绝对路径。

动态插件允许 CSP 的 blob 模块，不使用 eval、Function 构造器或脚本 unsafe-inline。第三方依赖应打包到入口；CodeMirror 扩展使用 context.editor.codeMirror.state/view 提供的宿主构造器，避免重复打包核心导致实例冲突。

## Obsidian 插件移植

固定源码版本 → 检查许可证 → 列出所需功能和 API → 复用许可允许的算法 → 替换文件、编辑器与界面接口 → 检查启停和多工作区行为。核心 API 的公开类型定义并不包含其实现，旧插件不能直接安装。

## 编辑器扩展示例

通过宿主模块建立扩展，清理函数由实例自动登记：

```javascript
const { EditorView } = context.editor.codeMirror.view;
context.registerEditorExtension(EditorView.theme({
  '.cm-activeLine': { backgroundColor: '#587ead18' },
}));
```

移植 Obsidian 插件时，vault 文件读写映射 files；命令与设置映射 addCommand/addSettings；Markdown 处理器映射 registerCodeBlock；ItemView 需要重写为 registerPanel。metadataCache、Dataview 查询、Node/Electron 能力和 Obsidian DOM 结构没有直接等价实现，应按具体插件需求增加宿主 API。

插件命令的 shortcut 字段目前用于显示提示，尚未绑定全局快捷键；可编辑快捷键属于后续交互清单。files.list 列出单个目录，递归扫描需由插件逐层调用。插件不提供直接 Obsidian API 兼容层。
