# 04 · 插件开发

## 安装与运行

使用自有 SDK，不能直接安装 Joplin/Obsidian 插件。JS/TS 打包为自包含 ESM，含 manifest.json、main.js 和可选 styles.css。默认导出带 onload(context) 的类，可提供 onunload()。随包 examples/plugins/reading-time 是实际隔离示例。

```json
{
  "id": "reading-time",
  "name": "阅读时间",
  "version": "2.0.0",
  "sdkVersion": 2,
  "runtime": "isolated",
  "description": "当前笔记阅读时间",
  "permissions": ["editor", "commands", "views"]
}
```

在设置选择清单目录安装，检查目标目录的 editor/files:read/files:write 权限再启用。实例、权限、启停、数据按工作目录隔离。升级会停用/清空授予权限，保留数据；卸载移除代码和各目录配置，写盘失败会回退。安全模式、关闭目录、停用、替换版本都会清理资源和取消异步加载。

## SDK 2 隔离模式

默认 isolated 在不透明 iframe 内的 Worker 执行，没有宿主 DOM、Node/Electron 或直接网络。SDK 消息桥逐次校验请求，文件访问由 Rust 核对目录/权限。清单用途声明本身不能替代实际授权。

| 接口 | 用途 |
|---|---|
| addCommand | 注册命令/默认快捷键，进入命令面板并可自定义绑定 |
| addSettings | 文本/数字/开关设置，字段合法且唯一 |
| files.read/write/list | 目录内读取、版本保护写入、列出单个目录 |
| editor.getText/getSelection、insert/replaceSelection | 原工作目录笔记快照和编辑，需要 editor 权限 |
| loadData/saveData | 工作目录独立数据，保存不强制启用 |
| onEvent/onFileChange | 文件/目录/设置事件 |
| addMenuItem/addToolbarItem | 把已注册命令放入插件菜单和工具栏 |
| registerHtmlPanel、registerListColumn | 净化 HTML 面板和详细列表文本列 |
| showDialog | 由字段定义显示表单，返回输入或 null |
| notice/register | 提示与资源清理 |

隔离桥的注册/文件/数据保存/表单可异步等待；loadData、编辑器读取为更新后的快照。注册返回清理函数，宿主也会统一清理。命令 ID 自动加插件/工作目录命名空间，快捷键与核心命令同一系统。

```javascript
export default class MyPlugin {
  async onload(context) {
    await context.addCommand({
      id: 'count', name: '统计当前笔记', shortcut: 'Ctrl+Alt+K',
      run() { context.notice(`当前字数：${context.editor.getText().length}`); },
    });
    await context.registerHtmlPanel('summary', '插件面板', '<p>插件已启用</p>');
  }
}
```

事件：file:opened/changed/saved/renamed/deleted、workspace:activated、settings:changed。数据绑定创建实例时工作目录，切换页签不会改写目标。

## 显式可信模式与旧 SDK

runtime: trusted 在宿主页面执行，需 host:full 授权，拥有完整页面能力。可额外使用 registerPanel/registerCodeBlock/registerEditorExtension。CodeMirror 扩展使用 context.editor.codeMirror.state/view 的宿主模块，避免重复打包另一份核心。

```javascript
const { EditorView } = context.editor.codeMirror.view;
context.registerEditorExtension(EditorView.theme({
  '.cm-activeLine': { backgroundColor: '#587ead18' },
}));
```

SDK 1 接口保留，默认隔离；依赖旧 DOM 的插件需明确 trusted 并取得授权。隔离模式不提供 DOM 回调。清单用途可为 files:read/files:write/editor/commands/views/settings/network/host:full；声明 network 不会开放 Worker 网络。

## 仓库与移植

支持自己的 HTTPS JSON 索引，结构为 plugins 数组，每项 manifest/downloadUrl/sha256；ZIP 包含清单/入口/样式，下载先核对 SHA-256，升级后重新授权。当前没有公共插件市场。

Obsidian 插件移植流程：固定源码版本、审查插件/依赖授权、拆出算法/界面需求、替换 API、验证多目录和生命周期。vault 映射 files，命令/设置映射 addCommand/addSettings，处理器/ItemView 重写为可信代码块/面板或隔离 HTML 面板，editor/workspace 映射 editor/onEvent。

metadataCache、Dataview、Obsidian DOM、Node/Electron 与专用索引没有通用兼容层，应按具体插件增加能力。验收覆盖同名文件多目录、启停/卸载、写盘冲突、异步清理和快捷键。用户尚未指定具体第三方插件源码。
